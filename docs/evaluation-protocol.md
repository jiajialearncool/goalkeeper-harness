# 第一版正式对照协议

## 比较对象与指标

目标是评估独立 Harness 是否改善长程编码任务的成功交付与综合消耗。三组统一 `gpt-6-astra / xhigh`，使用同一 ChatGPT 账号：

| 组别 | 执行系统 | 配置 |
|---|---|---|
| Codex | CLI 0.159.0 app-server | 原生 Goal、子 Agent、压缩和会话恢复 |
| 完整 GoalKeeper | 独立 Responses 接入 | 四项机制开启 |
| 受控基线 | 同一 GoalKeeper 基础设施 | 四项机制关闭，保留普通摘要、基础记忆、相同角色和最终检查 |

Codex 服务端与内部不可配置、不可观测的处理列为产品对照限制。GoalKeeper 与受控基线共用 64k 工作上下文配置；Codex 保留原生压缩。低窗口压力测试、pilot 和办公演示分别报告，不计正式得分。

主指标是无需额外人工救援、通过全部独立验收的任务比例。报告硬约束通过率、全部尝试的可观测用量与时间，以及全部尝试消耗除以成功数。输入加输出构成 token 总数；缓存输入、推理输出已在其中，不能重复相加。用量不完整时明确标记，不能声称总体 token 更低。订阅不是零消耗，不能直接换算成 API 账单。

## 预算与用时

36次尝试，每次最多1,800秒、100万可观测 token，包含主 Agent、子 Agent、摘要、复核和重试。合计上限 **1,080分钟（18小时累计执行时间）、3,600万 token**。用户计划中的1,800分钟累计值按36×30校正为1,080分钟；单次1,800秒不变。

四并发全部跑满预算理论4.5小时，另预留约1.5小时用于准备、评分和报告，争取约六小时。三并发理论6小时还没有评分余量；二并发9小时，一并发18小时。真实总时间还受吞吐、资源等待与评分负载影响；优先取得36次有效结果，额度不足允许延长。

接入检查累计50,000 token。pilot 与 F1 合计最多24次，每次30分钟/100万 token。基础设施诊断另有200万 token上限，用途独立记录；不得挪作正式重试。新增付费服务预算零。

## 题目和信息一致性

先冻结 Harness，再创建12道新题：3重构、3迁移、2排错、2需求变更、2会话恢复。新增代码、需求组合或业务数据，不得只重命名开发题。固定初始代码、依赖、输入、可修改范围、业务探针、反馈、验收与预算。依赖提前安装，正式工具网络全部关闭，不含需要本地服务端口的任务。

每次独立目录与记忆；三组按题交错，轮换先后顺序。公共探针根据实际业务结果触发反馈，不使用某组自己的阶段状态。恢复分别模拟关闭程序后恢复原会话，以及新建会话读取共同交接包。允许使用各自原运行资料；外部信息相同。程序关闭/重启只是模拟跨天恢复，不能写成真实跨天停机实测。

## 评分和冻结

执行结束先停止全部执行 Agent，保存文件快照，再由工作区外的程序评分。Agent 可改项目测试，但不能读写隐藏评分包。评分要求测试完整收集，无跳过、无重复、无缺失，并验证文件范围和快照未改变。参考解应通过，关键约束反例应被拒绝。

冻结源码提交、依赖锁、模型、提示词、四项开关、上下文、并发、权限、Codex版本、题目、评分器、反馈与运行顺序的版本和校验值。正式结果出现后不修改实现或标准来挽救这一轮。

超时、预算耗尽、Harness崩溃和未达标均计失败。确认的外部故障或额度耗尽记资源中断，继续同一次尝试并保留已有消耗。禁止选择最佳重跑结果。评分过程异常只恢复评分；评分器错误使受影响三组统一作废，修正、重新冻结后重新评测。

## 统计和结论

成功率按相同任务配对，使用两个不一致结果概率的保守精确区间，保证至少95%覆盖。这样即使12题全部持平，也不会用退化的[0,0]区间错误宣称不劣。非劣界限预设为负5个百分点：区间下界至少−5%才支持不劣，下界大于0才支持领先。

消耗差使用按任务配对的10,000次重采样区间，固定随机种子。主报告同时保留失败消耗和“所有消耗÷成功数”，不只看成功任务消耗。一次运行不能估计同题多次波动，结论只适用于这批题和固定条件。

观察值较高、证据支持领先、未能证明领先分别陈述。36次结果、独立评分和复现资料完整后，评测 Goal 可以完成，不要求 GoalKeeper 必须超过 Codex。
