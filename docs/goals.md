# 两个 Goal 的完成条件

本文保存完成条件，没有创建 Codex Goal。工程检查通过不等于 Goal 完成。

## 搭建 GoalKeeper 并完成 pilot

需要全部满足：

1. 工作台可操作；自身授权、固定模型与真实工具闭环通过，同一 ChatGPT 账号核对通过。
2. 四项机制、状态、记忆、子 Agent、预算与工具权限完成；当前源码对应的工程检查全部通过，没有跳过。
3. 完整版与受控基线共用配置；四项开关外的差异可以核对，基础记忆不恢复被关闭的目标或进度机制。
4. GoalKeeper 12 次、Codex 与受控基线各四次基础 pilot 取得有效结果。最多四项诊断预留之一用于 F1，原失败保留。工程故障有原因、修正提交与诊断记录。
5. 至少一项真实多阶段任务通过独立验收。需求变更、关闭程序恢复原会话、新建会话交接均有实际记录。
6. 并发 1、2、4 依次实测，冻结选择通过检查的最高并发；离线模拟不能代替真实吞吐。
7. F1 实际完成销售分析、可编辑文件与改版，独立核对数据、公式改动效果、原生图表和文件完整性，并完成视觉检查。确定性开发样例不满足此项。
8. 保存运行说明、pilot 报告、证据和程序提交；正式新题未参与调试。通过全部条件后生成不可覆盖的冻结清单。

自身授权或真实接入尚未完成时，这个 Goal 尚未完成。pilot 未超过 Codex 不妨碍完成。

## 完成冻结后的正式对照评测

需要全部满足：

1. 冻结后制作并验证 12 道新的离线题：三道重构、三道迁移、两道排错、两道变更、两道恢复。新增代码、需求组合或业务数据，不能只改名称。
2. 三组每题一次，共 36 次，全部有效。超时、预算耗尽、程序崩溃、任务未达标均是有效失败；未解决的资源中断尚未完成。
3. 停止执行并保存快照后独立评分；配置、输入、顺序与冻结校验一致，无跨尝试记忆或答案泄漏。
4. 交付逐题结果、三组汇总、硬约束、置信区间、全部消耗、额度等待、评分时间、人工救援、失败原因和证据索引。
5. 明确区分“观察到更高”“证据支持领先”“未能证明领先”；说明单次运行、12题样本和 Codex 内部不可观测部分的限制。
6. 保存源码、锁文件、提示词、权限、输入、评分器、反馈规则、日志与交付物，使同一协议可以再次运行。

完成条件是取得可信对照结果。是否超过 Codex 由冻结后的数据决定。
