# 第1题：按整题消耗验证全流程优化

本轮只运行 GoalKeeper 第1题（M1），不运行第2题或其他组。原题包、反馈、15项独立验收和30分钟/100万可观测token上限保持不变；模型为 gpt-6.1-sol / xhigh，继续使用现有订阅。

## 已实施的规则

- 主 Agent 与 Reviewer 共用完整工具事务整理和同版本可见文件去重。较旧的成功调用与结果一起转为原文引用；失败工具及其结果和未完成过程保留。已结束步骤的加密推理不继续反复发送，保留可见推理摘要、最新步骤的推理和全部失败证据；完整历史仍保存。
- 主任务保持要求、阶段、检查证据和恢复交接。恢复前核对实际文件；仍然有效的检查按既有依赖规则复用，无法确定范围时继续全量检查，不放宽依赖策略。
- 程序在全部阶段通过或进入预算收尾时切换到收尾模式。收尾模式先做必要检查、修复和交付，跳过非必要摘要；工作输入仍受64,000 token硬限制，不能静默删除失败证据来续跑。
- 复核优先接收实际生产文件/配置修改和已有检查结果，测试及依赖仍可按需读取；首次复核失败后只优先检查新修改，同时带入原缺陷。复核每个连续执行分段最多180秒，窗口结束保存进度后继续同一复核，仍共用原任务总预算，全任务最多两个子Agent，给主任务检查、修复与交付保留120秒。没有结构化复核结论不算通过。
- 保存复核已完成轮次、读取结果和已消耗时间，资源中断后继续同一个子任务，不重启整段复核、不清零预算。目标或文件变化后旧复核进度失效。
- 提示与程序进展一起要求代码、相关测试和检查组成工作单元；已发现缺陷先修复实现，再补必要回归，不只生成失败测试。仍使用既有批量工具和自动阶段推进，不新增额外规划模型调用。

## 验证与解释边界

先运行全部本地工程检查及新增故障模拟，再保存源文件校验清单，运行一条全新M1开发记录。只对资源中断作有限原尝试续跑；程序故障、超时、未验收计入结果，不挑最好的一次。

逐项记录合格交付、阶段及复核结果、读取正文与重复次数、摘要请求、各角色用量和耗时、用量完整性，以及源文件/题包是否改变。历史Codex13分29秒/30.22万token仅作诊断参照；低约5%的12分49秒/28.71万token是目标，不是预测或保证。

必要复核保持上一条M1开发记录中的交付门槛。前两次历史记录的复核流程不同，不将它们当作严格同条件性能对照。连接等待另记；缺失用量只报告可观测下界。最终记录保存在 outputs/m1-global。

## 首次验证暴露的问题及跟进

首次运行 826d859ec39b499ab3d4780b199a33ae，代码版本 b89bc96。独立15项通过，但未完成复核，100万可观测token阈值停止，实际记录1,003,223 token、1,385.28秒。题包及执行期间源文件未改变。

- 第一轮复核被180秒窗口中断，不能把这个中断直接当作质量未通过并重新启动整段复核。现在窗口结束归类为保存进度后继续，沿用原读取、子Agent计数和总任务预算。
- 第二次主Agent主动发起的复核发生 RemoteProtocolError；原工具异常处理把资源错误转换为普通工具失败。现在资源错误向上返回，停止主循环并按原尝试续跑。
- 已结束子调用引用先前指向整个历史归档，按文件查询可能读出大量相邻、重叠或加密材料。现在返回确切 call: 引用，读取仅包含该调用及结果。
- 复核名额用完且存在已确认未解决问题时，停止并报告未完成，避免继续反复请求 finish、检索和测试。

新增模拟检查覆盖上述路径；修正后另存新版本，只对第1题进行开发复验，记录在 outputs/m1-global-followup，不覆盖首条失败记录。
